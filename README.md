# Devnet WayVR Watch Manager v0.1.14

Devnet WayVR Watch Manager is a GTK4 desktop tool for customising the **standard WayVR wrist watch** on Linux while keeping WayVR itself untouched.

It preserves the normal WayVR controls and adds live PC information, Quest controller battery percentages, extra time zones, IPD/session information, a desktop preview, backup/restore and a built-in Doctor.

> **Release status:** v0.1.14 uses the live-watch behaviour confirmed working on the reference Quest 3 + WiVRn + WayVR 26.8.0 setup. The v0.1.13/v0.1.14 changes are desktop-preview cleanup only. The current source passes 21 automated functional tests plus syntax/XML/SVG checks. Real WayVR/Quest rendering is still a hardware-side acceptance step.

Made by: Devnet (idea + testing) + ChatGPT (implementation help)

---

## What it does

The standard WayVR watch remains the base. Devnet adds:

- AMD GPU temperature and usage
- AMD VRAM usage
- CPU temperature and usage
- RAM usage
- PC uptime
- up to four extra time zones
- optional IPD display
- optional VR session timer
- reorderable PC metrics
- Quest left/right controller battery percentages over wireless ADB
- in-VR **PC- / PC+** toggle for the added information section
- live desktop preview using the WayVR HMD and controller icons
- backup and restore of a pre-existing custom `watch.xml`
- Doctor / Debug checks for WayVR, `wayvrctl`, ADB, controller batteries and the installed watch

The HMD battery remains WayVR/WiVRn native. Devnet only supplies the controller percentages that the current WiVRn/Monado battery-device path does not expose to WayVR.

---

## How the Quest controller batteries work

On the reference setup WayVR receives the HMD battery, but not left/right Touch Plus battery status from WiVRn/Monado.

Devnet therefore reads the Quest controller percentages from Android `OVRRemoteService` through ADB and writes them into permanent watch widgets with `wayvrctl panel-modify`.

The controller widgets sit **beside** WayVR's runtime-owned `devices_root`, not inside it. This prevents WayVR from deleting them during tracked-device refreshes.

The live watch uses copies of WayVR's own left/right controller SVGs. The desktop preview also uses the WayVR HMD/controller images so the preview matches the live watch more closely.

## Reference setup

Developed for and live-tested with:

- CachyOS / Arch-based Linux
- KDE Wayland
- Meta Quest 3
- WiVRn
- WayVR 26.8.0
- AMD Radeon RX 9070 XT
- wireless ADB for Quest controller battery data

The package is intentionally focused on this stack rather than claiming universal VR-overlay compatibility.

## Software requirements

Required:

- Python 3
- PyGObject / GTK4
- WayVR 26.8.0-compatible watch format
- `wayvrctl`
- systemd user services

For CachyOS / Arch:

```fish
sudo pacman -S --needed python python-gobject gtk4
```

For Quest controller battery percentages:

```fish
sudo pacman -S --needed android-tools
```

The Quest must already be authorised for ADB. Wireless ADB is optional; if it is unavailable the controller values safely fall back to `--%` and the rest of the watch continues working.

## Before installing

Installing the application **does not immediately modify the WayVR watch**.

The watch is changed only when you open the manager and press:

**Save & Apply to VR**

On the first apply, restart the full VR stack once so WayVR loads the user-theme `watch.xml`. After that, live text/visibility changes are sent through `wayvrctl`.

## Install / upgrade

Download the current release ZIP, extract it, then in Fish:

```fish
cd ~/Downloads
unzip -o devnet-wayvr-watch-manager-v0.1.14.zip
cd devnet-wayvr-watch-manager-v0.1.14
chmod +x install.sh uninstall.sh bin/*
./install.sh
```

Open the manager from the KDE application menu or run:

```fish
devnet-wayvr-watch-manager
```

Then press **Save & Apply to VR** when you are ready to install the watch override.

## Normal use

The metrics service runs as a systemd **user** service. The manager can change the watch configuration and preview without requiring root.

The in-VR **PC- / PC+** button hides or restores only the Devnet information card. It does not close the standard WayVR watch.

Controller batteries are polled from the Quest at a slower interval than the normal PC metrics to avoid unnecessary ADB traffic.

---

## Run the Doctor

From the GUI choose **Run Doctor / Debug**, or run:

```fish
devnet-wayvr-watch-doctor
```

The Doctor checks:

- WayVR process/version
- active OpenXR runtime environment
- watch override path and XML
- required Devnet widget IDs
- `wayvrctl` IPC / input state
- metrics service state
- ADB availability and current Quest target
- left/right `OVRRemoteService` battery parsing
- controller update commands generated by the metrics bridge
- recent relevant `/tmp/wayvr.log` lines

The latest report is saved to:

```text
~/.config/devnet-wayvr-watch-manager/doctor-latest.txt
```

The Doctor also includes a temporary **77% / 88%** live controller-widget test.

---

## Restore the standard WayVR watch

Use **Restore standard watch** in the GUI.

If there was already a user `watch.xml` before Devnet first applied its override, the original file is backed up under:

```text
~/.config/devnet-wayvr-watch-manager/backups/
```

Restore puts that previous override back. If there was no prior override, Devnet removes its watch file and WayVR falls back to the built-in standard watch.

---

## Uninstall

From the extracted package directory:

```fish
./uninstall.sh
```

The uninstaller removes the Devnet application/service files. It restores/removes the Devnet watch override according to the saved backup state rather than modifying `/usr/bin/wayvr`.

## Files installed

Main application:

```text
~/.local/share/devnet-wayvr-watch-manager/
```

Launchers:

```text
~/.local/bin/devnet-wayvr-watch-manager
~/.local/bin/devnet-wayvr-watch-doctor
~/.local/bin/devnet-wayvr-watch-metrics
~/.local/bin/devnet-wayvr-watch-toggle
```

Configuration and backups:

```text
~/.config/devnet-wayvr-watch-manager/
```

WayVR user-theme override:

```text
~/.config/wayvr/theme/gui/watch.xml
```

User service:

```text
~/.config/systemd/user/devnet-wayvr-watch-metrics.service
```

Desktop launcher:

```text
~/.local/share/applications/devnet-wayvr-watch-manager.desktop
```
